## A. ข้อมูลตั้งต้นใหม่ (ต้องสร้าง)

| องค์ประกอบ | รายละเอียด (ตัดสินแล้ว) |
|---|---|
| **ตารางวันหยุดนักขัตฤกษ์** | กรอกมือต่อปี (วันที่ + ชื่อวันหยุด) — รวมวันราชการและหยุดพิเศษของ กฟภ. โดยไม่แยกชนิด |
| **ชนิดวันลา (LeaveTypes — master)** | ผู้ใช้เพิ่มชนิด / แก้ `defaultDaysPerYear` ได้เอง — เป็นที่ดึงตอน generate สิทธิ์ปีถัดไปและตอนคำนวณ prorata พนักงานใหม่ — **ค่า seed:** ลาป่วย 30 / พักร้อน 7 / ลากิจ 3 วันต่อปี |
| **บันทึกวันลา (Leave)** | ละเอียดระดับนาที (start–end) — อ้าง `leaveTypeId` — frontend มีปุ่ม "ลาทั้งวัน" แต่ส่งเป็นช่วงเวลา |
| **สิทธิ์วันลารายคน (LeaveEntitlements — snapshot)** | เก็บรายคน รายปี รายชนิด `entitledDays` — generate แล้ว**ตัดขาดจาก default** + endpoint generate ทั้งปีถัดไปให้ทุกคน + พนักงานใหม่ frontend คำนวณ prorata **ปัดขึ้น** ให้อัตโนมัติ แก้ไขได้ตามดุลยพินิจก่อนบันทึก |
| **ช่วงเวลาทำงานมาตรฐาน** | จันทร์–เสาร์ 08:00–17:00 (อาทิตย์หยุด) |

### กติกาสิทธิ์วันลา

- นับตาม **ปีปฏิทิน** (1 ม.ค. – 31 ธ.ค.)
- **ไม่สะสมข้ามปี** (รีเซ็ตทุกปี)
- เริ่มงานกลางปี → prorata ตามจำนวนเดือนที่เหลือ (เดือนที่เริ่ม = เดือนแรก) แล้ว**ปัดขึ้น**เป็นจำนวนเต็มวัน
- Enforce แบบ: **บล็อกเฉพาะ "ลงเกินยอดคงเหลือทั้งปี"** — สัดส่วนรายเดือน (เช่น พักร้อน 7/12 ≈ 0.58 วัน/เดือน)
  **ไม่บล็อก** เป็นดุลยพินิจหัวหน้างาน
- วันที่ลงลาไม่ได้ (เกินสิทธิ์) → ถือเป็น **ขาดงาน** (worker ไม่ได้ค่าจ้างวันนั้น / driver โดนหัก)

### การแก้ไขกลางปี (snapshot semantics)

Entitlement รายคนเป็น **snapshot** ตัดขาดจาก default ตั้งแต่ generate — ดังนั้น:

| เคสกลางปี | วิธีจัดการ (ตัดสินแล้ว) |
|---|---|
| แก้ `defaultDaysPerYear` ของชนิด | มีผลกับ **generation ครั้งถัดไปเท่านั้น** — สิทธิ์ที่ให้ไปแล้วไม่ขยับ ถ้าต้องการให้มีผลปีปัจจุบันทั้งบริษัท (เช่น กฎหมายเปลี่ยนกลางปี) = script ad-hoc แก้ snapshot รายคน นอกระบบ |
| แก้สิทธิ์**รายคน** | **แก้ได้ตลอดปี** ผ่าน UI โดยตรง (แก้ row ใน LeaveEntitlements ของคนนั้น) |
| แก้ยอดจน**ต่ำกว่าที่ใช้ไปแล้ว** (ใช้ 5 แก้เหลือ 3) | **อนุญาต** — ยอดคงเหลือติดลบได้ ผลคือคนนั้นลาชนิดนี้ต่อไม่ได้จนกว่าจะปรับยอด (block ตามกฎ "ไม่เกินยอดคงเหลือ") |
| เพิ่มชนิดวันลาใหม่ | เพิ่มใน LeaveTypes ได้ แต่ไม่มีใครมีสิทธิ์ชนิดนั้นปีนี้อัตโนมัติ — เติมรายคนผ่าน UI หรือ script แก้ DB ถ้าทั้งบริษัท (เคสหายาก ยอมรับได้) |
| ลบชนิดวันลา | **ห้ามลบ** ถ้ามี Leave หรือ Entitlement อ้างอยู่ — ใช้ `isActive` ปิดการใช้แทนการลบ |

### การคำนวณยอดคงเหลือ (คำนวณสด ไม่เก็บ cache)

```
remaining = entitledDays − usedDays

entitledDays ← LeaveEntitlements (รายคน รายปี รายชนิด)
usedDays     ← Σ จากตาราง Leave ของ (คนนั้น, ปีนั้น, ชนิดนั้น)
```

- **ไม่เก็บ `usedDays` ซ้ำใน LeaveEntitlements** — source of truth เดียวคือตาราง Leave
  (กัน drift เมื่อแก้/ลบ/ลาย้อนหลัง — query ใหม่ทุกครั้ง ข้อมูลต่อคนต่อปีไม่กี่ร้อยแถว เร็วพอ)
- หน่วยภายในตอนคำนวณเป็น**นาที**: `entitledMinutes = entitledDays × 480` —
  กฎ block "ลงไม่เกินยอดคงเหลือ" เทียบนาทีกับนาที แสดงผลค่อยแปลงเป็นวัน
- ช่วงลาที่คร่อมพักเที่ยง 12:00–13:00 → **ไม่นับเป็นเวลาลา** (ใช้ logic เดียวกับชั่วโมงทำงาน)
  — ลาทั้งวัน 08:00–17:00 = 480 นาที = ใช้สิทธิ์ 1 วันพอดี

## B. กฎการบันทึกลา (validation)

1. ลาได้เฉพาะช่วงเวลาทำงานปกติ **08:00–17:00** — **ยกเว้นพนักงานกะ** (มี flag กะอยู่แล้ว) ลาได้ทั้ง 24 ชม.
2. พนักงานปกติที่ถูกดึงไปทำ**กะดึกเฉพาะครั้ง** → ลาช่วงนั้น**ไม่ได้** (ถือเป็นงานเพิ่ม ได้ชั่วโมงทำงานเท่านั้น ไม่เข้าเคส "ลา")
3. **ห้ามซ้อนทับทั้ง 2 ทาง:** เวลาลา ↔ เวลาทำงาน (TimeEntry), เวลาลา ↔ เวลาลา (Leave)
4. **work + leave ≤ 8 ชม./วัน** — ส่วนเกินต้องลงเป็น OT แยกเสมอ
5. **ห้ามบันทึกลาในวันนักขัตฤกษ์** (ต้องแตกช่วงลารอบวันหยุดเอง)
6. **ห้ามลาคาบข้ามปี** (1 ม.ค.) — ลา 30 ธ.ค.–2 ม.ค. ต้องแตกเป็น 2 รายการแยกต่อปี
7. ลาย้อนหลังได้ทุกวัน — ผลเงิน**เข้ารอบถัดไป** (ไม่ย้อนแก้รอบที่จ่ายไปแล้ว)

## C. สูตรเงิน Worker

```
ต่อ 1 วัน: paidMinutes = ชั่วโมงทำงานจริง + ชั่วโมงลา
    ≥ 480 นาที → dailyRate (เต็มวัน)
    < 480      → ชม.เต็ม × hourlyRate + นาทีเศษ × minuteRate   (ย่อยหน่วย)

วันนักขัตฤกษ์ ไม่มาทำงาน → + dailyRate อัตโนมัติ
วันนักขัตฤกษ์ มาทำงาน   → ต้องลง pattern holiday_2x / holiday_3x เท่านั้น (ห้าม pattern ปกติ)
                           และยังได้ holiday pay 1 เท่า (auto) ซ้อนอีกชั้น
OT → สูตรเดิม
rate ทุกอย่างใช้ WageRate ณ วันนั้น (effectiveFrom/To) — ปรับเรทกลางรอบจัดการด้วย retroactive ตามเดิม
```

หมายเหตุ: สูตรเดิม (< 8 ชม. คิดรายชม.) ยังใช้ — สิ่งที่เพิ่มคือ "เวลาลามารวมเติมวัน" และ holiday pay

## D. สูตรเงิน Driver

```
เงินพื้นฐาน = monthlyRate (จาก WageRate)
วันทำงาน = จันทร์–เสาร์ · คาดหวัง 8 ชม./วัน
วันที่ไม่มีชั่วโมงคาดหวัง = อาทิตย์, วันนักขัตฤกษ์, วันลา (ลารายชั่วโมงก็ไม่โดนหักชั่วโมงนั้น)

ชั่วโมงขาด = Σ ทุกวันทำงาน: max(0, 480 นาที − ชั่วโมงทำจริง − ชั่วโมงลา)
เงินหัก   = ย่อยหน่วย: จำนวนวันเต็ม × dailyRate + ชม.เต็ม × hourlyRate + นาที × minuteRate
            (ตัวอย่าง: ขาด 2 วัน 3 ชม. 10 นาที = 2×daily + 3×hourly + 10×minute)

OT = ลงได้เฉพาะนอกช่วง 08:00–17:00 (จ–ส) — คิดเงินตามสูตรเดิม, ไม่ชดเชยชั่วโมงคาดหวัง
วันหยุด (อาทิตย์ + นักขัตฤกษ์) = ลงเวลาปกติ (REGULAR) ไม่ได้ — ลงได้แค่ OT (+ค่าที่พัก)
  (backend reject 422 + UI แสดง "หยุด" ล็อกแถว — เพิ่ม 3 พ.ย. 2026 หลัง user ทัก 13 ต.ค.)
ค่าที่พัก = ACCOMMODATION ตามเดิม
REGULAR entry ของ driver ใช้เพียง "บอกว่ามาทำงานกี่ชั่วโมง" — ไม่มีผลต่อเงินพื้นฐาน
ชั่วโมงทำจริง = นาที entry หักพักเที่ยง 12:00–13:00 ถ้าคร่อม (ใช้ util เดียวกับ worker และนาทีลา)

เข้าใหม่กลางเดือน → สลับเป็นจ่ายรายวัน: (วันทำงานสุทธิ × dailyRate) + OT + ค่าที่พัก
  วันทำงานสุทธิ = วันที่มี entry + วันลา + วันนักขัตฤกษ์ (จ–ส เท่านั้น) นับตั้งแต่ startDate
หักจนยอดติดลบ   → clamp ที่ 0
```

### สรุปยอด (Payroll summary) ของ Driver — โครง JSON ใหม่

- เพิ่ม field **`monthlyRate`** และ **`absentMinutes`** (นาทีขาดสะสมทั้งรอบ — ตัวเดียว)
  ตอนแสดงผล frontend/รายงานค่อยแปลงเป็น "2 วัน 3 ชม. 10 นาที" / เงินหักย่อยหน่วยแตกจากนาทีตัวเดียวกันตอนคำนวณ
- **`deductionAmount` เก็บเฉพาะ correction/เรียกคืน** (จ่ายไปแล้วเรียกคืน) — ห้ามเอาการหักขาดงานไปปน
- หน้า "จ่ายเงินพนักงาน" (v1): **worker และ driver ใช้รูปแบบสรุปเหมือนกัน** (คล้ายแผ่น driver —
  worker: จำนวนวันทำงาน/แรง × ค่าจ้างวันละ + OT + รวม) — ตารางรายวันแบบแผ่นเบิกเป็นของฝั่งเบิก (อนาคต)

* วันที่ 23 เป็นวันหยุดนักขัตฤกษ์ ทุกคนได้ 1 แรง โดยไม่ได้เข้างานจริง

**ตรวจแล้ว:** นายไก่ 14×560 = 7,840 · นายกก 11.5×366 = 4,209 (ครึ่งวัน = 0.5 แรง) · SSO = 5% ของรวมเป็นเงิน (392 = 5%×7,840) ·
จ่ายสุทธิ = รวมเป็นเงิน − SSO · "จ่ายผู้รับจ้างวันละ" (672/559/481) = **contract price ฝั่งเบิก** (ไฟฟ้าจ่ายเรา — ไม่ใช่ค่าจ้างพนักงาน)

**ยืนยันกฎจากแผ่นจริง → ตรงกับ spec:** วันนักขัตฤกษ์ = 1 แรงอัตโนมัติ (= holiday pay dailyRate) ·
ครึ่งวัน 0.5 แรง (= entry < 480 นาที คิดรายชม.) · อาทิตย์ 2 กะ ×2 = 4 แรง (= 2 entry holiday_2x) · เสาร์เป็นวันทำงาน ·
อาทิตย์ปกติ = 0 (worker ไม่ได้โดนหัก เพราะคิดตามแรงที่ลงจริง)

**⚠️ ฝั่งเบิก (ตารางรายวัน + contract price) ไม่อยู่ใน scope v1** — v1 ทำเฉพาะฝั่งจ่ายเงินให้พนักงาน ซึ่งรูปแบบหน้าจ่ายของ worker และ driver ใช้**แบบสรุปเหมือนกัน** (คล้ายแผ่น driver)

1. **ลาออกกลางเดือน** — **แยกเป็น Phase 2 ไม่ block v1** (เจ้าของงานหาข้อมูลเพิ่ม)
   - ตัวอย่างที่เคยเห็น: "ทำงาน 16 วัน = 16 × ค่าจ้างรายวัน"
   - แนวทางที่เสนอไว้ (ยังไม่ตัดสิน): เพิ่ม field `endDate` (วันสุดท้ายทำงาน) ใน Employee
     เมื่อ endDate ตกในรอบจ่าย → สลับสูตรรายวันเหมือนเคสเข้าใหม่ (นิยามวันสุทธิใช้อันเดียวกับเข้าใหม่)

## ข้อสังเกตที่ต้องระวังตอน implement (จากโค้ดปัจจุบัน)

- ปัจจุบันโค้ดหักพักกลางวัน 12:00–13:00 กับทุก entry ที่ `shiftType=REGULAR` (driver เป็น REGULAR เสมอ) —
  ตอนเปลี่ยนสูตร driver ต้องระวังว่าชั่วโมงทำจริงจะนับยังไงกับพักเที่ยง (spec ใหม่ยังไม่ได้พูดถึง — ต้องถามตอนทำแผน)
- Worker ลง pattern ปกติในวันนักขัตฤกษ์ต้องถูก **reject** (ตามกติกา C) — backend ต้องเช็คกับตารางวันหยุด
- สูตร driver ใหม่ทำให้ `paidValue` ราย entry ของ driver ไม่ใช้ตัวเงินพื้นฐานแล้ว —
  โครงสร้าง PayrollRelate/สรุปยอด (workingDays, regularAmount) ต้องนิยามความหมายใหม่
- ระบบ dev-only — เปลี่ยน schema/reset ข้อมูลได้
